## 1. Domain & Architecture Boundaries

- **EXECUTION CONTROL AUTHORITY:** Single canonical gate enforcing environment admission, kill-switches, and pre-submission TX1 reservations.
- **EXECUTION ATTEMPT:** Immutable attempt record created and committed in PostgreSQL before HTTP transmission.
- **EXECUTION ENVIRONMENTS:** Explicitly admitted `TESTNET`; `SIMULATED` and `DRY_RUN` supported; `LIVE`, `MAINNET`, and `PRODUCTION` strictly prohibited fail-closed.

- **PRODUCTION GUARD:** `fapi.binance.com` and production targets rejected fail-closed with typed `Val04B2BoundaryError`.
- **SUBMISSION RESERVATION:** Pre-submission TX1 atomically writes `ExecutionAttempt(RESERVED)` and `CanonicalOrder(PENDING_SUBMISSION)` to PostgreSQL before network call.
- **SUBMISSION IDENTITY:** Deterministic `clientOrderId` (`ax-intent-...`) generated by Axodus and used as the authoritative lookup key on Binance.
- **CLIENT ORDER ID ↔ PROVIDER ORDER ID:** Axodus client order ID remains canonical identity; Binance `orderId` (`28591022090`, etc.) mapped as observed metadata.
- **SUBMISSION STATES:** `RESERVED` → `SUBMITTING` → `SUBMITTED_UNKNOWN` (on drop) → `ACKNOWLEDGED` / `OPEN` (on query/reconcile).
- **AMBIGUOUS SUBMISSION & RECONCILIATION BEFORE RETRY:** Under simulated ACK loss, order marked `SUBMITTED_UNKNOWN`. Bounded query reconciliation via `clientOrderId` recovers remote state (`NEW`) without blind retry.
- **BLIND RETRIES:** Exactly `0`.
- **CANONICAL ORDER:** Immutable identity with optimistic locking (`orderVersion`) and append-only event projection (`canonical_order_events`).
- **ORDER STATES:** `PENDING_SUBMISSION` → `SUBMITTED_UNKNOWN` → `OPEN` → `CANCEL_PENDING` → `CANCELLED`.
- **PROVIDER OBSERVATION:** Normalized immutable observation (`ORDER_STATUS`) deduplicated and applied via `ReconciliationAuthority`.
- **CANONICAL FILL:** Immutable fill records with exact 12-decimal arithmetic; overfills strictly blocked; `ACK != FILL` preserved.
- **CANCELLATION & RACE HANDLING:** Controlled cancel transitions through `CANCEL_PENDING` to `CANCELLED`.
- **KILL SWITCH & SAFETY HALT:** System/instrument halts immediately reject new attempts; active orders reconciled/cancelled per policy.
- **RESTART RECOVERY:** Non-terminal state discovery recovers pending orders on startup and reconciles without duplicate submissions.
- **EXECUTION RESULT:** Terminal state finalized only upon verified reconciliation (`CANCELLED_UNFILLED` / `FILLED`).
